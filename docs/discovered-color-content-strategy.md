# 발견 색 활용 콘텐츠 전략

마지막 갱신: 2026-07-26 KST
상태: **Hue Canvas 대표 콘텐츠 승인, M2-2 뒤 최우선 시각·조작·Canvas 2D 프로토타입 대기**
상세 제품 명세: `docs/hue-canvas-product-spec.md`

## 1. 결정

Hue Room은 첫 출시와 현재 critical path에서 완전히 보류한다. 이를 축소하거나 다른 이름의 방으로 바꾸지 않는다.

Hueday의 발견 색 대표 콘텐츠는 **Hue Canvas**다.

> 완성한 3x3의 미션 색을 발견 횟수만큼 사용할 수 있는 반투명 유리 타일로 모아, 큰 가상 캔버스에 자유롭게 그림을 만들거나 선 도안을 채운다.

이 결정은 사용자가 명시적으로 승인한 다음 아이디어를 결합한다.

- 이름은 Hue Canvas다.
- 4x4 같은 작은 고정판이 아니라 확대·축소하며 쓰는 큰 캔버스다.
- 발견한 색의 횟수가 작품에서 사용할 수 있는 같은 색 타일 수가 된다.
- 사용자는 자유롭게 그리거나 검은 선 도안을 불러와 내부를 채운다.
- 도안 크기를 조절하면 필요한 논리 셀 수가 자동으로 바뀐다.
- 기본 질감은 반투명 스테인드글라스·교회 유리 공예다.
- 앱과 Play Store에 현실적으로 구현 가능한 Canvas/SVG 규칙을 사용하고 HEX별 에셋을 만들지 않는다.

## 2. Hueday 핵심 루프와 연결

```text
오늘의 미션 색
→ 일상에서 비슷한 색 8개 발견
→ 중앙 색을 포함한 3x3 완성
→ mission_hex 사용 가능 칸 +8
→ Hue Palette에서 색과 횟수 확인
→ Hue Canvas 자유 그림 또는 도안 채우기
→ 저장·리믹스·원본 3x3 열기
→ Story/Hueprint/Relay로 공유
→ 작품을 더 채우기 위해 다음 색 발견
```

Hue Canvas는 단순 그림 앱이 아니다. 사용할 색을 현실에서 직접 찾아야 한다는 제약이 Hueday만의 수집 이유가 된다.

## 3. 색 재료 계약

- 기준 색은 사진 RGB 추출값이 아니라 완성한 post의 `mission_hex`다.
- 주변 사진 8장을 채운 3x3 한 페이지를 완성할 때 해당 중앙 `mission_hex`의 사용 가능 칸이 8 늘어난다. `usableCells = 완료 페이지 수 × 8`이다.
- 첫 사진인 색 씨앗은 진행을 안전하게 저장하지만 주요 색 수량을 열지 않는다.
- 같은 색을 여러 번 완성하면 그 작품에서 사용할 수 있는 타일 수도 늘어난다.
- 사용량은 작품별 배치 한도이며 영구 소모가 아니다.
- 지우거나 바꾸면 수량이 돌아온다.
- 같은 색은 여러 작품에서 재사용할 수 있다.
- 새 색을 얻으면 기존 작품을 복사하거나 편집해 리믹스할 수 있다.
- 결과물의 색은 원본 3x3·날짜·색 이름으로 역추적할 수 있다.
- 빈 날, 낮은 매칭률, 연속 일수 손실을 재료 수량에 연결하지 않는다.

## 4. 캔버스와 도안

### 자유 캔버스

- 충분히 큰 유한 가상 격자와 pan/zoom을 제공한다.
- 사용자가 작품 크기와 완성 시점을 정한다.
- 빈 셀을 전부 저장하지 않고 칠한 셀만 저장한다.
- 탭·드래그 칠하기, 지우기, undo/redo가 첫 조작이다.

### 도안 캔버스

- 검은 그라우트/선과 채울 영역만 있는 도안을 제공한다.
- 사용자가 도안을 확대·축소하면 논리 셀 수와 필요한 색 수량이 다시 계산된다.
- 칠하기 전 자유 조절을 허용한다.
- 칠한 뒤 크기 변경은 파괴적 덮어쓰기보다 복사본·미리보기를 기본으로 한다.
- 도안 자체가 정답 색을 강요하지 않는다.

### 재질

- 첫 재질은 반투명 스테인드글라스다.
- 공통 텍스처·빛·그라우트 규칙에 임의 HEX를 주입한다.
- HEX 수만큼 PNG/SVG를 만들지 않는다.
- 화면은 Canvas 2D를 우선 사용하며 성능 증거 없이 WebGL·게임 엔진·새 렌더 의존성을 넣지 않는다.

## 5. Hue Palette

Hue Palette는 Hue Canvas 안의 재료함이다.

- 색 칩
- 사용자 색 이름
- 총 발견 횟수
- 현재 작품에서 사용 중인 수
- 남은 사용 가능 수
- 원본 3x3 목록
- 최근 사용 색

독립적인 팔레트 선반만으로 대표 콘텐츠를 끝내지 않는다. 색 수집은 캔버스에서 실제 행동과 결과물로 이어져야 한다.

## 6. 반복 사용 이유

- 한 색을 한 번 더 찾으면 작품의 같은 색 영역을 한 칸 더 채울 수 있다.
- 다른 색을 찾으면 기존 작품의 분위기를 바꾸거나 새 도안을 시작할 수 있다.
- 큰 캔버스는 한 번에 끝낼 필요가 없어 장기적인 개인 프로젝트가 된다.
- 작은 도안은 빠른 완성 보상을 준다.
- 자유 캔버스는 사용자 개성을 만든다.
- 월간 Hueprint는 그달 얻고 사용한 색과 작품 진행을 회고한다.
- 결과물은 누가 더 많이 모았는지보다 `내가 실제로 발견한 색으로 만들었다`는 이야기를 가진다.

스트레스 방지:

- 작품 완성을 강제하지 않는다.
- 색이 부족할 때 이미 칠한 타일을 회수하지 않는다.
- 연속 일수, 공개 순위, 희귀도, 뽑기, 소멸 재화를 사용하지 않는다.
- 자동 저장·undo·복사본으로 실수 비용을 낮춘다.

## 7. 현재 코드 활용과 필요한 변화

재사용:

- `posts.mission_hex`: 발견 색 기준
- `posts.grid_images` 또는 `client_meta.gridImages`: 원본 3x3 출처
- 날짜·색 이름·저널: 기억 연결
- Story/`html2canvas`: 현재 공유 흐름 참고
- 기존 색상 계산 helper: 대비·명도 보정 참고
- Capacitor Filesystem: 로컬 recipe와 파생 이미지 후보

필요한 변화:

- 부분 진행과 완성 3x3의 상태 분리
- 완성 post 기반 색 수량 집계
- 로컬 우선 Hue Canvas recipe
- 작은 cloud snapshot과 owner RLS
- Canvas 2D 렌더러
- 원본 post 역추적
- Android 성능·앱 종료 복구

저장·동기화는 `docs/data-storage-sync-and-cost-strategy.md`를 따른다.

## 8. 개발 순서

1. M1에서 1장 진행·8장 완성 계약을 코드에 반영한다.
2. M2-2에서 로컬 우선 저장·복구·최소 분석 기반을 완료한다.
3. M4에서 Hue Canvas 430x932 시안, 실제 Canvas 2D 시각·조작·성능 스파이크를 먼저 검증하고 승인받는다. 빈 Hue Canvas 또는 Coming Soon 전용 탭은 만들지 않는다.
4. 승인 뒤 M2-3에서 정상 동기화된 날짜의 local master를 사용자가 수동 정리하는 기능을 구현한다. 자동 삭제는 금지하며 복구 불가 경고와 사용자 확인을 둔다.
5. 이어서 M3에서 전체 팩보다 최소 일상 미션 팩을 구현한다.
6. M5에서 출시용 Hue Canvas·Palette·recipe·색 수량·Color Rhythm 보상·export를 완성한다.
7. M6에서 Hueprint·Color Capsule에 작품을 연결한다.
8. M7에서 Relay 공유를 연결한다.
9. M8~M9에서 디자인·접근성·성능·보안·실기기 출시 검증을 끝낸다. Android capture → force-stop → offline/online retry는 출시 전 필수 QA로 유지한다.

M4 시각 승인 전에 전체 에셋, 복잡한 DB schema, 대형 렌더러를 먼저 만들지 않는다.

## 9. 추후 확장 후보

### 우선 보존

- **Hue Charm**: 발견 색을 모듈 파츠로 만들고 여러 Charm을 연결하는 컬렉션. 작은 색 면적과 아기자기·여성 편향을 해결한 새 형태가 필요하다.
- **Hue Deck**: 완성 3x3과 기억을 카드로 모으는 시스템. 단순 카드 목록이 되지 않도록 조합·도전·공유 규칙이 필요하다.

### 재질·도안 확장

- **Hue Loom**: 직조 패턴을 Hue Canvas 재질 또는 도안으로 흡수
- **Hue Glass**: Hue Canvas 기본 재질의 고급 변형
- **Hue Bouquet**: 꽃 도안·계절 Story/Hueprint 팩

### 장기 후보

- Hue Cinema: 움직이는 회고 export
- Hue Constellation: 날짜·미션 관계를 연결한 지도
- Hue Soundscape: 색 조합 기반 짧은 사운드
- Hue Passport: 장소를 강제하지 않는 문맥별 스탬프
- Hue Garden/Creature: 죄책감과 아트 비용을 해결할 증거가 생길 때만 재검토
- Hue Room: 별도 아트 파이프라인 대비 반복 사용 가치가 증명될 때만 재개

후보는 승인된 기능이 아니다. 사용자와의 새 결정 없이 로드맵의 현재 작업이나 구현 범위로 자동 승격하지 않는다.

## 10. 수익화 연결

- 기본 Hue Canvas, 기본 유리 재질, 기본 도안, 발견 색 사용, 로컬 저장, 기본 export는 무료다.
- 고급 도안·재질·편집 도구는 `Hueday Studio` 1회 구매 후보로 둔다.
- 고화질 백업·자동 기기 복구·클라우드 휴지통은 `Hueday Cloud` 구독 후보로 둔다.
- Hue Charm·Hue Deck 같은 별도 콘텐츠를 자동으로 Studio에 약속하지 않는다.
- 사용자가 얻은 색과 무료 보상을 결제로 잠그지 않는다.

세부 가격과 무료/유료 경계는 `docs/product-growth-strategy.md`의 `Monetization Model`을 따른다.

## 12. 방향 변경 방지 계약

다음 변경은 Codex가 임의로 하지 않는다.

- Hue Canvas를 다른 대표 콘텐츠로 교체
- 발견 횟수 기반 사용량을 영구 소모 재화로 변경
- 기본 캔버스나 얻은 색을 유료화
- 스테인드글라스 기본 재질을 다른 방향으로 교체
- 3x3 완료가 아닌 첫 사진에 주요 재료 보상 지급
- Hue Room 재개
- 무한 캔버스·실시간 협업·생성형 AI를 첫 출시 필수로 추가

변경이 필요하다고 판단하면 현재 결정, 충돌 근거, 사용자 영향, 최소 2개 선택지를 텍스트로 먼저 제시하고 명시적 승인을 받은 뒤 문서와 코드를 바꾼다.
