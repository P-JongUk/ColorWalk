# Hueday AI 모델·추론·모드 선택 가이드

이 문서는 Hueday 작업을 시작할 때 품질, 속도, 비용을 함께 보고 Codex 설정을 고르는 기준입니다. 고정된 최고 사양을 항상 쓰지 않고, **필요한 결과를 안정적으로 내는 가장 낮은 사양**에서 시작합니다.

## 판단 근거 우선순위

1. 현재 Codex에서 실제 선택 가능한 모델과 OpenAI 공식 최신 가이드
2. 작업의 모호성, 영향 범위, 되돌리기 비용, 검증 난이도
3. 이 저장소의 과거 성공·실패 기록과 검증 결과
4. 사용자가 제공한 `Artificial Analysis Coding Agent Index v1.1` 비용-성능 그래프

외부 벤치마크 그래프는 방향을 잡는 보조 자료입니다. 그래프의 API cost는 Hueday 작업 한 건의 실제 요금이 아니며, 종합 점수가 특정 제품 기획이나 버그 수정의 품질을 보장하지 않습니다. 그래프에서는 Luna 계열이 저비용 구간에서 효율적이고 Sol이 최고 품질 구간에 있지만, 최종 선택은 작업 적합성으로 결정합니다.

공식 기준은 다음 문서를 우선 확인합니다.

- [OpenAI 모델 가이드](https://developers.openai.com/api/docs/guides/latest-model)
- [OpenAI 모델 목록](https://developers.openai.com/api/docs/models)
- 저장소의 실제 기본값: `C:\Users\JongUk\.codex\config.toml` (2026-07-22 확인 당시 Luna + high)

## 작업 시작 시 선택 순서

1. 결과물과 `완료 조건`을 한 문장씩 정합니다.
2. 반복·정형 작업인지, 일반 개발인지, 모호하고 고가치인 판단인지 분류합니다.
3. 아래 표에서 가장 낮은 충분한 모델과 추론 단계를 고릅니다.
4. 계획이 먼저 필요한지, 목표를 여러 차례 계속 추적해야 하는지 별도로 판단합니다.
5. 현재 설정이 충분하면 그대로 진행하고, 변경이 유의미할 때만 사용자에게 한 줄로 추천합니다.

### 승급·강등 규칙

- Luna 결과에서 누락이나 재작업이 반복되면 Terra로 올립니다.
- Terra에서 요구사항 충돌, 다중 시스템 판단, 고위험 결정이 남으면 Sol로 올립니다.
- Sol을 썼더라도 범위가 확정된 구현 반복 단계에서는 Terra 또는 Luna로 내립니다.
- 추론 단계는 `medium`에서 시작하는 것이 기본입니다. 여러 단계·자료·트레이드오프가 있으면 `high`, 최고난도 검증에만 `xhigh` 또는 Max를 씁니다.
- Fast는 지연 시간이 실제 병목일 때만 사용합니다. 기본은 표준 속도입니다.
- Ultra는 하위 에이전트를 사용하는 모드이므로 이 프로젝트의 단일 에이전트 규칙상 사용하거나 추천하지 않습니다.

## 계획 모드와 목표 모드

### 계획 모드 사용

다음 중 하나라도 해당하면 계획 모드를 먼저 사용합니다.

- 요구사항이 모호하거나 선택지가 둘 이상이고 결과가 크게 달라짐
- 세 개 이상의 의존 단계나 여러 시스템이 연결됨
- 제품 전략, 아키텍처, 마이그레이션, 보안처럼 잘못된 방향의 재작업 비용이 큼
- 구현 전 사용자와 우선순위 또는 성공 지표를 합의해야 함

한두 파일의 명확한 수정, 단순 확인, 이미 승인된 계획의 구현에는 계획 모드를 쓰지 않습니다.

### 목표 모드 사용

목표 모드는 하나의 구체적인 완료 목표를 여러 차례 작업하며 끝까지 추적해야 할 때만 사용합니다. 예: `공개 베타 출시 준비를 완료하고 모든 출시 검증을 통과한다.` 대략적인 아이디어 대화, 짧은 계획 작성, 단일 수정에는 사용하지 않습니다. 목표를 설정할 때는 세부 지침을 이 문서나 별도 계획 파일에 두고 목표 문장은 짧게 유지합니다.

## 매 작업에서 Codex가 알릴 형식

설정 변경이 품질이나 비용에 의미가 있을 때, 구현 전에 다음 형식으로 짧게 알립니다.

> 추천: `Terra · high · 계획 모드 켬 · 목표 모드 끔 · Fast 끔` — 여러 파일의 일반 기능 개발이며, Sol까지 필요한 고위험 판단은 아닙니다.

아주 작은 후속 질문이나 현재 설정이 이미 적절한 경우에는 같은 안내를 반복하지 않습니다. Codex는 실행 중인 대화의 모델을 임의로 바꿨다고 주장하지 않으며, 변경이 필요하면 사용자가 고를 정확한 설정을 알려줍니다.

## 프롬프트 기본 골격

```text

맥락: 먼저 읽을 문서, 현재 상태, 사용자 대상
제약: 바꾸면 안 되는 것, 승인 경계, 비용·기간 제약
완료 조건: 어떤 결과와 검증이 있으면 끝인지
출력: 원하는 순서와 깊이
```

같은 규칙을 여러 번 반복하지 않습니다. 프로젝트의 지속 규칙은 `AGENTS.md`와 이 문서에 두고, 작업 프롬프트에는 달라지는 목표·맥락·제약·완료 조건만 씁니다.

## 갱신 규칙

- 모델 제공 범위나 공식 권장이 바뀌면 공식 문서를 다시 확인하고 이 문서를 갱신합니다.
- 같은 유형의 작업에서 재작업 또는 비용 낭비가 반복되면 `docs/ai-memory/`의 근거와 함께 선택표를 조정합니다.
- 제품 전략이 바뀌어도 모델 이름만 좇지 말고 작업 위험도와 완료 조건을 먼저 판단합니다.
