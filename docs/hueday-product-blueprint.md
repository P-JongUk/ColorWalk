# Hueday 전체 제품 청사진

마지막 합의 정리: 2026-07-23 KST
문서 역할: 지금까지 사용자와 Codex가 합의한 Hueday 전체 방향을 한곳에서 확인하는 최상위 제품 source of truth
상세 실행 순서: `docs/hueday-development-roadmap.md`

## 1. 제품 한 문장

> Hueday는 오늘의 미션 색을 일상에서 발견해 3x3으로 모으고, 그 색을 나만의 작품 재료로 사용해 색 정체성을 키우고 친구와 가볍게 나누는 카메라 기반 컬러 다이어리다.

Hueday는 산책 기록 앱, 사진 SNS, 꾸미기 게임 중 하나만을 목표로 하지 않는다. 현실의 작은 관찰을 `컬러 헌트`, `창작`, `회고`, `공유`로 이어 주는 하나의 경험을 만든다.

## 2. 출시 원칙

- 최대한 빠르게 출시한다.
- 빠른 출시를 핵심 요소를 잘라낸 최소 앱으로 해석하지 않는다.
- 성공 가능성을 만드는 실현 가능한 요소는 완성도 있게 포함한다.
- 구현·운영·심사 난도가 출시 가치에 비해 지나치게 큰 기능만 근거를 남기고 후순위화한다.
- 속도를 이유로 인증, RLS, 데이터 손실 방지, 개인정보 보호, 접근성, 실기기 QA를 생략하지 않는다.
- 날짜를 임의로 늘여 잡는 장기 일정 대신 의존 관계가 있는 critical path를 따른다.

## 3. 사용자와 감정 목표

### 주요 사용자

- 한국의 10대와 20대 초반 베타 사용자
- 사진을 올리고 싶지만 얼굴·외모·인기 비교에는 피로한 사람
- 다이어리를 매일 길게 쓰기 어렵지만 작은 기록은 남기고 싶은 사람
- 색, 무드, 사진, 꾸미기, 수집을 좋아하는 사람
- 학교, 통학, 카페, 집, 여행 같은 일상을 새롭게 보고 싶은 사람

### 사용자가 느껴야 하는 감정

- `오늘은 이 색이 어디에 있을까?`라는 작은 호기심
- 평범한 일상에서 색을 찾아낸 기쁨
- 3x3 한 페이지를 채우는 완성감
- 내 색이 실제 창작 재료와 작품이 되는 소유감
- 시간이 쌓일수록 나만의 색 흔적이 선명해지는 정체성
- 친구와 비교하지 않고 같은 색을 서로 다르게 발견하는 친밀함

### 만들지 않을 감정

- 하루를 놓쳐서 모든 기록이 무너졌다는 실패감
- 친구보다 점수가 낮다는 비교 불안
- 펫이나 방을 방치했다는 죄책감
- 색 일치율이 낮아 틀렸다는 평가
- 사진을 공개하지 않으면 기능을 쓸 수 없다는 압박
- 결제하지 않으면 내 기록을 잃는다는 불안

## 4. Hueday의 고유 핵심 루프

```text
오늘의 상황에 맞는 미션 팩
→ 현지 날짜마다 추천·선택하는 새 미션 색
→ 일상에서 비슷하다고 느끼는 색 찾기
→ 첫 사진으로 오늘의 색을 잠그고 1~8개의 장면 기록
→ 8칸을 채우면 완성되는 3x3 컬렉션
→ 짧은 색 이름과 기록
→ 발견 색 재료함·Hueprint 작품 축적
→ 스토리·작품·Relay 카드 공유
→ 다음 색을 발견하러 돌아오기
```

이 루프에서 빠지는 기능은 별도 앱처럼 느껴질 가능성이 높다. 새 기능은 `발견`, `수집`, `표현`, `회고`, `관계` 중 하나 이상을 분명히 강화해야 한다.

## 5. 확정된 전체 제품 결정

### 5.1 컬러 헌트와 3x3

- 중앙에는 오늘의 미션 색을 둔다.
- 사용자는 주변에서 그 색과 비슷하다고 느끼는 대상 사진을 찾아 주변 8칸을 채운다.
- 사용자 기기의 현지 날짜가 바뀌면 새로운 미션 색 선택을 시작한다. 어제 색과 사진 수를 오늘의 활성 미션으로 넘기지 않는다.
- 첫 색은 날씨·시간·선택적 대략 위치에 맞춰 추천한다. `다른 색`을 누른 첫 3회까지는 같은 맥락의 다른 색을 추천하고, 이후에는 전체 정적 색 목록에서 현재 색을 제외한 각 색을 같은 확률로 보여 준다.
- 첫 사진의 `이 사진 사용`을 확정하기 전에는 색을 바꿀 수 있다. 첫 사진을 확정하면 그 현지 날짜의 미션 색을 잠그고 자정 전까지 바꾸지 않는다.
- 첫 사진은 안전하게 보존되는 `오늘의 색 발견`이자 `오늘의 색 씨앗`이다. 1장 이상이면 그날의 유효한 색 기록이며, 8장 3x3 페이지 완료와는 구분한다.
- 2~7장은 그날 모은 색 장면으로 보존한다. `미완성`, `실패`, `밀림`으로 부르지 않는다.
- 8장을 모두 채우면 오늘의 미션과 중앙 미션 색을 포함한 3x3 한 페이지가 완성된다.
- 발견 색 창작 재료, Hueprint 반영, 완성형 공유 결과물 같은 주요 보상은 완성된 3x3을 중심으로 연결한다.
- 8장을 당일 필수로 강제하지 않는다. 현지 자정이 지나면 그날 기록은 당시 사진 수로 닫고, 다음 날은 새 색을 선택한다. 닫힌 과거 기록에는 사진을 추가하지 않는다.
- 자정에 카메라 화면을 강제로 중단하지 않는다. 앱 foreground 복귀나 다음 사진 확정 전에 날짜 변경을 확인하고 어제 기록 보존과 오늘 새 색 선택을 안내한다.
- 1~7장 기록에 보상 손실, 연속 일수 초기화, 죄책감을 유발하는 문구를 사용하지 않는다.
- 사진의 실제 RGB를 자동 추출해 정답을 판정하지 않는다.
- 색 매칭률과 퍼센트를 제품 UI에서 제거한다.
- `발견한 색`의 데이터 기준은 사진 분석값이 아니라 저장된 `mission_hex`다.
- 3x3은 Hueday를 한눈에 설명하는 대표 결과물로 유지한다.

### 5.2 산책이 아닌 일상 전체

- 서비스의 중심 문구는 `오늘의 색 발견`과 `일상 속 컬러 헌트`다.
- 컬러 산책은 없애지 않고 여러 미션 팩 중 하나로 둔다.
- 집, 학교, 캠퍼스, 통학, 대중교통, 카페, 편의점, 도서관, 회사, 여행, 날씨, 시간, 관심사에서 색을 찾는다.
- 위치 추적을 하지 않아도 미션 팩을 사용할 수 있어야 한다.
- 날씨와 시간은 추천 근거이지 사용 제한이 아니다.

### 5.3 부담 없는 지속 구조

- 연속 일수보다 누적 발견과 유연한 주간 목표를 중심으로 한다.
- 사용자는 한 주 2일·3일·5일 같은 색 리듬을 선택할 수 있다.
- 하루나 한 주를 놓쳐도 누적 색, 아이템, 챕터는 줄지 않는다.
- `기록이 끊겼어요`보다 `새 색이 기다리고 있어요` 같은 복귀 문구를 사용한다.
- 공개 순위, 친구 스트릭, 보상 회수, 소멸 재화는 넣지 않는다.

### 5.4 발견 색 활용 대표 콘텐츠

- Hue Room은 첫 출시 핵심과 현재 개발 critical path에서 완전히 제외하고 출시 후 가설로 보류한다.
- 대체 대표 콘텐츠는 **Hue Canvas**로 확정했다.
- 완성한 3x3의 `mission_hex`는 원본 사진과 날짜가 연결된 색 재료가 되고, 같은 색을 발견한 횟수가 한 작품에서 배치할 수 있는 해당 색 타일 수가 된다.
- 색은 영구 소모하지 않는다. 타일을 지우거나 바꾸면 사용량이 돌아오고 여러 작품에서 다시 사용할 수 있다.
- 사용자는 확대·축소 가능한 큰 가상 격자에서 자유롭게 그리거나, 크기를 조절할 수 있는 검은 선 도안을 불러와 내부를 채운다.
- 기본 재질은 임의 HEX를 공통 렌더 규칙으로 표현하는 반투명 스테인드글라스다. 색상별 에셋을 만들지 않는다.
- 새 색을 얻으면 과거 결과물을 그 색으로 리믹스할 수 있고, 결과물의 색을 누르면 원본 3x3과 일기로 돌아갈 수 있어야 한다.
- 상세 제품·조작·기술·승인 게이트는 `docs/hue-canvas-product-spec.md`, 후보와 보류 상태는 `docs/discovered-color-content-strategy.md`를 따른다.
- 기존 Hue Room 명세와 로컬 시안은 삭제하지 않고 출시 후 재검토 증거로만 보존한다.

### 5.5 Hueprint와 Color Capsule

- Hueprint는 저장된 색을 주간·월간·계절·연간 단위로 보여 주는 개인 색 정체성이다.
- 월간 Hueprint는 대표 색, 완성한 3x3, 자주 사용한 색 이름, 대표 사진을 9:16 결과물로 만든다.
- Hueprint는 사용자가 직접 만든 작품과 월간 자동 회고를 같은 색 정체성으로 연결한다.
- Color Capsule은 과거 색 기록을 시간이 지난 뒤 다시 만나는 회고 기능이다.
- 빈 날을 실패로 표시하지 않고 기록된 날과 색을 중심으로 보여 준다.
- 감정이나 성격을 AI가 단정하는 진단 문구는 사용하지 않는다.

### 5.6 Color Relay

- 성공 루프: `개인 일일 색 기록 → 편집 없이도 공유하고 싶은 3×3/9:16 카드 → 받은 친구의 나도 이 색 찾기 → 두 결과의 공동 팔레트·엽서·Hueprint → 다음 기록으로 재진입`.
- 개인 기록은 공유 없이도 완결되며, 공유와 친구 참여는 무료 성장 행동이다. 공개 랭킹·색 매칭 점수·강제 streak는 사용하지 않는다.
- 사용자가 오늘의 컬러 카드나 미션 링크를 친구에게 보낸다.
- 받은 사람은 로그인 없이 제한된 카드와 `나도 이 색 찾기`를 볼 수 있다.
- 저장·동기화가 필요할 때 가입한다.
- 두 사용자의 결과는 점수나 일치율 없이 나란한 색 조각, 엽서, 공동 팔레트로 보인다.
- 공유 링크는 만료·폐기가 가능하고 위치·EXIF·내부 사용자 ID·다른 비공개 기록을 노출하지 않는다.
- 댓글, 좋아요 수, 팔로워, 공개 검색은 첫 출시 핵심이 아니다.

### 5.7 실제로 쓰는 보상

- 배지는 잠금/해제 아이콘만 보여 주는 장식이 아니다.
- 보상은 발견 색 재료, 창작 재질·구도, 스토리 프레임, Hueprint 레이아웃, Relay 타일처럼 실제로 쓸 수 있어야 한다.
- 출시 전 실제 사용자가 없으므로 3·7·14·30 보상은 완성 3×3 페이지 수 기준으로 즉시 전환한다. 출시 후에는 이미 획득한 무료 보상을 회수하지 않는다.
- 무료로 획득한 보상은 유료 팩이 생겨도 완성된 무료 아이템으로 남는다.
- 세부 기준은 `docs/colorwalk-reward-system.md`를 따른다.

## 6. 아직 사용자 승인 또는 실험이 필요한 결정

다음은 방향을 정했지만 구현 전에 증거가 더 필요한 항목이다.

게이트 1에서 `1장은 3×3 진행 시작, 8장은 한 페이지 완성과 주요 보상`으로 확정했고, 후속 결정에서 1장부터 유효한 일일 기록으로 인정했다. 첫 사진부터 저장·초안 복구가 가능한 현재 구현은 같은 현지 날짜 안에서 부담 없이 기록하고 이어가기 위한 기반으로 본다.

| 결정 게이트 | 현재 후보 | 확정 방법 |
| --- | --- | --- |
| Hue Canvas 시각·조작 | 제품·스테인드글라스 방향 승인, 실제 시안 미승인 | 430x932 핵심 상태와 Canvas 2D 프로토타입 사용자 선택 |
| Hue Canvas 가상 격자·저장 형식 | 256x256 희소 저장 시작 가설 | 10,000셀 Android 성능·복구·저장 크기 측정 |
| Hue Chapter 명칭·임계값 | 색 발견자 → Hue Keeper | 실제 진행 속도와 카피 테스트 |
| 첫 출시 창작 범위 | 기본 재질 1~3개와 결정적 SVG/Canvas | 복원성·내보내기·Android 성능 스파이크 |
| 첫 분석 도구 | 최소 이벤트만 우선 | 개인정보·비용·PWA/Android 호환 비교 |
| Color Relay의 무가입 범위 | 카드 보기와 첫 촬영 미리보기 | 보안·저장 경계 프로토타입 |

결정 게이트가 남았다는 이유로 전체 작업을 멈추지 않는다. 게이트 전에 안전하게 할 수 있는 구조 파악·와이어프레임·렌더 스파이크·테스트 설계를 먼저 한다. 다만 이미 승인된 제품 의미를 구현 편의에 맞춰 바꾸지 않는다.

## 7. 기능 체계

### A. 오늘의 색 발견

목적: 앱을 열 이유와 현실을 바라볼 작은 과제를 제공한다.

- 날씨·시간·계절 기반 기본 미션
- 사용자가 상황에 맞는 미션 팩 선택
- 중앙 미션 색과 색 이름
- 첫 추천 + 3회 맥락 추천 뒤 전체 색 균등 랜덤
- `오늘의 색 찾기` 단일 핵심 CTA
- 첫 사진 사용 확정 후 그날 미션 고정
- 기기 현지 날짜가 바뀌면 새 색 선택
- 위치 권한 거부 시에도 사용할 수 있는 fallback

### B. 3x3 컬렉션

목적: 단일 사진보다 Hueday다운 수집과 완성감을 만든다.

- 중앙 미션 색 + 주변 8장
- 촬영·앨범·네이티브 카메라 대체 경로
- 임시 초안과 복구
- 사진별 교체와 순서
- 8칸 완성 상태의 명확한 보상
- 1~7장도 유효한 일일 기록으로 보존
- 같은 현지 날짜 안의 안전한 이어 채우기와 자정 종료

### C. 저널과 색 이름

목적: 색에 개인적인 의미를 붙인다.

- 추천 색 이름
- 사용자가 직접 붙이는 이름
- 짧은 문장과 선택적 일기
- 글쓰기를 강제하지 않음
- 색·날짜·미션 팩과 함께 저장

### D. 스토리와 공유 결과물

목적: 발견을 외부에서 한눈에 이해되는 결과로 만든다.

- 3x3 중심 9:16 템플릿
- 미션 색, 이름, 날짜, 짧은 문장
- 범용 편집기보다 Hueday 고유 프레임
- 다운로드, Web Share, 네이티브 공유 fallback
- 일치율과 정확도 표현 제거
- 보상으로 얻은 프레임·스탬프를 실제 사용

### E. 미션 팩

목적: 산책하지 않는 날에도 일상에서 색을 찾게 한다.

초기 정적 팩:

- 집
- 학교·캠퍼스
- 통학·대중교통
- 카페·편의점
- 시간대
- 날씨
- 패션·음식·문구·인테리어
- 컬러 산책
- 계절·여행

처음에는 코드의 정적 config로 만들고 운영에서 자주 교체해야 한다는 증거가 생길 때만 DB/CMS로 옮긴다.

### F. 색 리듬과 보상

목적: 놓친 날의 불안을 만들지 않고 자주 돌아올 이유를 제공한다.

- 주간 2/3/5일 선택 목표
- 평생 누적 발견일
- 완성한 3x3 수
- 경험한 미션 팩
- 월간 참여
- Hue Canvas/Story/Hueprint 실제 창작 옵션 해금

### G. 발견 색 대표 콘텐츠

목적: 저장된 색을 직접 조합하고 다시 쓰는 소유 가능한 창작 재료와 작품으로 바꾼다.

- 원본 기록이 연결된 Hue Palette
- 발견 횟수 기반 스테인드글라스 타일 사용량
- 큰 자유 캔버스와 가변 크기 선 도안
- 새 색으로 과거 작품 리믹스
- 원본 3x3 재진입
- 기본 export와 9:16 Hueprint·Relay 연결

### H. Hueprint와 Capsule

목적: 시간이 흐를수록 앱을 떠나기 어려운 개인 기록 가치를 만든다.

- 주간 대표 색
- 월간 9:16 리캡
- 계절 챕터
- 과거 기록 재발견
- Hue Canvas 작품·월간 표지

### I. Color Relay와 가까운 관계

목적: 공개 피드 없이 색 발견 행동이 다음 사용자에게 이어지게 한다.

- 안전한 공유 링크
- `나도 이 색 찾기`
- 공동 팔레트·엽서·짝 타일
- 이후 2~8명 close circle
- 공개 비교·랭킹 없음

### J. 프로필과 색 정체성

목적: 팔로워 수가 아니라 사용자가 모은 색과 기억을 보여 준다.

- 대표 Hueprint Gallery
- 누적 팔레트
- Hue Chapter
- 자주 붙인 색 이름
- 획득 아이템·미션 팩
- 월간/계절 Hueprint

## 8. 첫 사용과 반복 사용 여정

### 첫 사용

1. Hueday가 무엇인지 한 문장으로 이해한다.
2. 오늘의 미션 색을 본다.
3. 권한과 가입 때문에 마법의 순간이 지나치게 늦어지지 않게 한다.
4. 추천 색을 고르고 첫 색 사진을 확정해 오늘의 색을 잠근 뒤 기록이 안전하게 저장되는 것을 확인한다.
5. 같은 날 원할 만큼 색 장면을 더 모으고 1~7장도 유효한 오늘 기록임을 이해한다.
6. 원하면 8장을 채워 오늘의 3x3 한 페이지와 주요 보상을 완성한다.
7. 첫 색 재료와 명확한 창작 보상을 본다.
8. 원하면 스토리 또는 링크를 공유한다.

### 반복 사용

1. 오늘 상황에 맞는 미션 팩과 새 추천 색을 확인한다.
2. 색을 선택하고 첫 사진으로 잠근 뒤 새로운 색 장면을 기록한다.
3. Hue Palette와 Hueprint에 새 색 타일과 조합 가능성이 생긴다.
4. 새 색으로 과거 작품을 리믹스하거나 원본 기록을 다시 본다.
5. 주간 색 리듬과 미션 팩이 부담 없이 진행된다.

### 돌아온 사용자

- 스트릭 파손 화면을 먼저 보여 주지 않는다.
- 마지막 기록과 작품은 그대로 기다린다.
- 오늘 할 수 있는 가장 작은 색 발견을 제안한다.
- 쉬었던 기간을 벌점이나 결손으로 만들지 않는다.

## 9. 비주얼 브랜드

전체 제품은 다음 감각을 유지한다.

- 부드럽고 감정적이지만 유아적이지 않음
- 10대·20대가 공유하고 싶을 만큼 트렌디함
- 따뜻한 아이보리, 세이지, 제한된 코랄 포인트
- 사진과 발견 색이 주인공
- 티켓·컬러 카드·종이 기록의 촉감
- 과도한 그림자, 유리 효과, 무거운 게임 HUD 금지
- 화면별 서로 다른 유행 스타일을 섞지 않음

Hue Canvas는 현재 선택한 `D — Chromatic Archive`의 모던하고 정돈된 외부 UI와 연결하되, 캔버스는 따뜻한 빛과 반투명 유리 질감으로 창작 보상을 준다. 생성 이미지가 아니라 실제 Canvas 2D/SVG 프로토타입으로 품질을 재현한 뒤 승인한다. Hue Room 시안은 현재 디자인 승인 범위에서 제외한다.

## 10. 개인정보와 안전

- 모든 개인 기록은 기본 비공개다.
- Browser code에는 Supabase publishable key만 둔다.
- service role은 Edge Function 또는 로컬 관리 도구에만 둔다.
- RLS는 owner 기준으로 유지하고 모든 새 테이블을 cross-user denial까지 검증한다.
- 공유 링크는 최소 필드, 만료, 폐기, 짧은 signed URL을 사용한다.
- 정확한 위치, EXIF, 내부 사용자 ID, 다른 비공개 기록을 공유하지 않는다.
- 미성년 사용자에게 공개 DM, 위치 탐색, 공개 인기 순위를 성급히 열지 않는다.
- 분석 이벤트에 사진, 일기 원문, 정확한 위치, 비밀번호 관련 정보를 넣지 않는다.
- 계정 삭제·데이터 export·복구 정책을 유료 장기 보관 전에 완성한다.

## 12. 성공 지표

### 활성화

- 앱 진입 → 미션 확인
- 미션 확인 → 첫 사진
- 첫 사진 → 유효한 오늘 기록과 색 잠금
- 1~7장 기록 → 같은 날 추가 수집 또는 자정 종료
- 8장 기록 → 3x3 완성
- 3x3 완성 → 주요 색 재료·Hueprint·공유 보상 확인

### 반복 사용

- D1/D7/D30 복귀
- 주간 저장일과 색 리듬 달성
- 완성 3x3 수
- Hue Palette/Canvas 재방문·작품 리믹스
- Hueprint 열기와 과거 기록 재방문

### 성장

- 스토리/작품/카드 공유율
- 공유 링크 열기
- `나도 이 색 찾기` 시작
- Relay 결과 완성

### 품질

- 권한 거부율
- 초안 복구 성공
- 이미지 업로드·저장 실패
- Hueprint 레시피 저장·복구 실패
- 공유 내보내기 실패
- PWA/Android 핵심 여정 성공

숫자는 충분한 세션이 쌓이기 전 가설로 기록하고 사실처럼 부풀리지 않는다.

## 14. 기술 원칙

- 현재 React/Vite/TypeScript, Zustand, Supabase, Capacitor, `html2canvas`를 우선 재사용한다.
- 패키지나 추상화를 추가하기 전에 기존 helper, 웹 표준, 네이티브 플랫폼 기능을 확인한다.
- 저장은 로컬 우선 + 작은 필수 클라우드 + 선택형 유료 고화질 백업을 따른다. 현재 코드는 아직 이 목표 구조를 완성하지 않았다.
- 사진의 로컬 마스터, 무료 미리보기, 공유 파생본, Cloud 고화질 백업을 구분하고 확인되지 않은 압축본을 유일한 사본으로 만들지 않는다.
- Hue Canvas는 Canvas 2D, 희소 셀 recipe, 로컬 자동 저장을 우선한다. 수천 DOM 셀, HEX별 에셋, 매 입력 네트워크 쓰기를 피한다.
- DB에 파생 가능한 색과 통계를 무작정 중복 저장하지 않는다.
- 정적 미션·아이템 카탈로그는 운영상 원격 수정 필요가 생기기 전 코드 config로 둔다.
- 새 DB 구조에는 migration, owner RLS, cross-user denial 검증, rollback/compatibility 계획이 필요하다.
- 화면 변경은 430x932 캡처와 기존 목업 비교를 통과해야 한다.
- 구현 완료는 코드 존재가 아니라 테스트·빌드·브라우저/Android QA·문서 정합성으로 판단한다.

## 16. 변경 계약

- 제품 방향을 바꾸면 이 문서와 전체 로드맵을 함께 검토한다.
- 하위 기능의 세부 설계는 기능별 문서에서 관리하고 이 문서에는 핵심 약속과 링크만 유지한다.
- 코드가 문서보다 앞섰다면 실제 검증 상태를 확인하고 모순을 해소한다.
- 확정, 실험, 구현 완료를 구분한다.
- 확정 방향을 바꾸거나 후보를 승격하려면 현재 결정·충돌 근거·영향·선택지를 사용자에게 먼저 제시하고 명시적 승인을 받는다.
- 외부 시장 사실은 확인 날짜와 원문을 유지한다.
- 매 작업 종료 시 Codex는 `docs/development-reference-guide.md`에 따라 영향 문서를 갱신하고 AI memory에 결과를 기록한다.
