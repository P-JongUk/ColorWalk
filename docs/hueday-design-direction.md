마지막 갱신: 2026-07-23 KST
상태: 게이트 1 확정, 게이트 2에서 D 외부 UI 선택, Hue Room 시안 중단, Hue Canvas 제품 방향 승인·시각 게이트 준비
작업 브랜치: `feature/design-direction`

이 문서는 디자인 조사와 승인 게이트의 결정·평가·다음 작업만 추적한다. 대형 이미지, 무드보드 원본, 외부 레퍼런스 캡처와 렌더 산출물은 `.design-references/`와 `.lazyweb/` 아래에 로컬 전용으로 보존한다.

## 판단 기준과 우선순위

디자인 제안은 다음 순서로 대조한다.

1. `docs/hueday-product-blueprint.md`의 핵심 경험과 제품 원칙
2. `docs/hueday-breakout-strategy.md`와 `docs/product-growth-strategy.md`의 차별화·성장 기준
3. `docs/colorwalk-reward-system.md`의 비처벌형 주요 보상 축
4. `docs/discovered-color-content-strategy.md`의 완전 대체 원칙과 승인 게이트
5. 현재 구현 코드와 기술 비용

현재 구현이 승인된 제품 방향과 다르면 제품 의미를 코드에 맞춰 바꾸지 않는다. 차이를 명시하고 후속 기능 브랜치의 구현 항목으로 분리한다. 새 디자인 방향이 기존 결정과 충돌하면 시안을 확장하기 전에 충돌 내용, 영향, 선택지를 사용자에게 제시한다.

## 게이트 1 — M1 수집 경험 의미

결정: **B의 보상 의미 유지 — 1장 일일 기록, 8장 미션 완료**

2026-07-23 후속 제품 결정에서 B안의 `1장과 8장 의미 구분`은 유지하되, 여러 날에 걸친 단일 페이지 이어 채우기는 `현지 날짜마다 새 컬러를 선택하고 자정에 그날 기록을 닫는 계약`으로 대체했다.

### 확정 계약

- 미션 색은 3×3 중앙에 배치한다.
- 사용자는 일상에서 미션 색과 비슷한 색을 찾아 주변 8칸을 채운다.
- 현지 날짜마다 날씨·시간·선택적 대략 위치를 반영한 색을 새로 추천한다. 최초 추천 뒤 `다른 색`은 하루 최대 6회다. 1~3회는 문맥 추천, 4~6회는 전체 큐레이션 균등 무작위이며 그날 이미 본 모든 색을 제외한다.
- 첫 사진을 확정하면 그날의 미션 색이 잠기며 더 바꿀 수 없다.
- 첫 사진부터 유효한 `오늘의 색 기록`이다. 다만 3×3 미션의 최종 완료나 주요 보상으로 부르지 않는다.
- 주변 8칸을 모두 채우면 오늘의 미션과 3×3 한 페이지가 완성된다.
- 완성된 페이지는 발견 색 재료, Hueprint, 공유 결과물 등의 주요 보상으로 이어진다.
- 2–7장도 그날의 유효한 기록이며 같은 날에는 이어서 채울 수 있다.
- 현지 자정에는 현재 장수 그대로 기록을 닫고 다음 날 새 색을 제안한다. 전날 기록을 오늘의 활성 미션으로 이어 채우지 않는다.
- 8장을 강제하지 않고 1–7장을 실패로 표시하거나 보상을 잃게 하지 않는다. 연속 일수 초기화와 죄책감을 유발하는 표현도 사용하지 않는다.
- 색 매칭 점수나 정확도는 사용자에게 노출하지 않는다.

### 현재 구현의 해석

현재 코드의 첫 사진 저장·저널 진입·초안 복구는 같은 현지 날짜 안에서 안전하게 기록하고 이어가는 기반이다. 재추천 횟수, 첫 사진 잠금, 현지 자정 마감, 1–7장 일일 기록과 8장 완성을 상태·카피·보상에서 구분하는 작업은 M1 후속 개발로 분리한다.

### 비교한 대안 A

A안은 `첫 사진으로 오늘 기록을 완료하고 나머지 7장은 선택 확장`하는 흐름이었다. 빠른 첫 결과와 낮은 진입 부담은 장점이다. 그러나 Hueday의 중심인 중앙 미션 색 기반 3×3 수집을 선택 장식으로 약화하고, 완성 페이지를 발견 색 창작·Hueprint·공유 주요 보상 축으로 삼는 제품 결정과 어긋나므로 채택하지 않았다. 실패안이 아니라 비교 검토한 대안으로 보존한다.

### 판단 교정

초기 비교에서 현재 코드의 편의와 빠른 첫 결과를 기존 제품 문서보다 과대평가해 A안을 추천했다. 이는 구현 상태를 제품 의도보다 앞세운 판단 오류였다. 이후 디자인 결정은 승인된 제품 방향을 먼저 기준으로 삼고 구현 차이는 후속 개발 항목으로 명시한다.

## 게이트 2 — 네 방향 1차 비교 범위

게이트 2에서는 네 방향을 한꺼번에 전체 화면으로 확장하지 않는다.

| 방향 | 1차 검증 질문 |
| --- | --- |
| A Modern Editorial Photo | 사진과 미션 색을 가장 강하게 보이게 하면서 감정적 온기를 유지하는가 |
| B Cozy Tactile Healing | 따뜻한 물성이 사진을 가리지 않고 10대·20대에게 유아적으로 보이지 않는가 |
| C Soft Paper Editorial / Diorama | 편집 디자인과 종이 물성이 Hueday의 수집·창작·공유를 하나의 언어로 묶는가 |
| D Chromatic Archive | 색 발견을 개인 아카이브처럼 새롭게 표현하면서 구현 가능성과 일상 사용성을 지키는가 |

각 방향에서 동일한 콘텐츠와 진행 상태로 다음만 비교한다.

- 무드보드 1개
- 430×932 홈 1개
- 중앙 미션 색과 주변 8칸을 보여 주는 430×932 3×3 수집 1개
- 당시 기준 동일한 방 구조와 부분 해금 상태의 Hue Room 질감 샘플 1개

평가 전에 제품 청사진, 성장 전략, 보상 시스템을 대조한다. 고유성·한국 10대/20대 매력·사진과 미션 색의 주인공성·정서적 피로도·확장성·접근성·구현 비용·유사 앱 위험의 가중 평가로 상위 두 방향만 다음 게이트로 보낸다.

### 게이트 2 결과와 범위 교정

- 외부 앱 UI는 사용자 선택에 따라 **D — Chromatic Archive**를 현재 작업 방향으로 둔다.
- 당시 Hue Room은 H1/H2/H3로 다시 비교했고 사용자는 H3의 구조와 제한적인 H2 패브릭을 선호했지만, 후속 레퍼런스 탐색이 사실적인 2.5D/3D 가구와 꾸미기 게임 수준으로 커졌다.
- 이 결과는 Hue Room 품질을 더 높이라는 신호가 아니라, 별도 아트 파이프라인이 제품 중심을 빼앗는다는 범위 경고로 판정했다.
- Hue Room 관련 보드와 시안은 `.design-references/05-hue-room/`에 역사적 자료로 보존하되 현재 승인·구현 대상에서는 제외한다.
- D 외부 UI 선택은 유지하지만, D 안에 들어갈 대표 콘텐츠는 Hue Room이 아니라 발견 색 완전 대체 콘텐츠로 다시 설계한다.

## 게이트 3 — Hue Canvas 시각·조작

다음 비교는 방이나 가구 시안이 아니라 동일한 사용자의 실제 3x3, `mission_hex`, 발견 횟수로 만든다.

사용자는 Hue Canvas, 큰 가상 격자, 발견 횟수 기반 색 사용량, 자유/가변 도안, 반투명 스테인드글라스 재질을 승인했다. 다음 게이트는 `docs/hue-canvas-product-spec.md`의 HC-2다.

- 빈 상태·Hue Palette·자유 작업·도안 크기 조절·완성/export를 같은 430x932 데이터로 비교한다.
- 생성 이미지와 실제 Canvas 2D/SVG 프로토타입을 함께 만들어 시각 재현성을 검증한다.
- D — Chromatic Archive의 정돈된 외부 UI를 유지하고 Canvas만 따뜻한 유리 빛으로 감정적 보상을 준다.
- 첫 시각·조작 승인 전에는 전체 에셋 세트나 복잡한 렌더러를 만들지 않는다.
- 산출물 상태와 D 드라이브 경로는 `docs/design-reference-index.md`에서 관리한다.
